# Лабораторна №8. Алгоритми пошуку

Варіант: `int[]` зі 100 000 чисел з [0; 20], X = 10, Y = 12, відсутнє значення 21.
Запит (b = 2): перший елемент, не менший за X. Варіант пошуку (c = 0): рекурсивний бінарний.
Увесь код — у `Program.cs`. Запуск: `dotnet run -c Release`.

## Завдання 1. Лінійний пошук

| запит | індекс | порівнянь |
|---|---|---|
| X = 10 | ___ | ___ |
| перший елемент | ___ | ___ |
| відсутнє 21 | -1 | ___ |

Третій запит найдорожчий, бо елемента немає і доводиться перевірити всі 100 000 елементів.

## Завдання 2. Бінарний пошук

| запит | порівнянь (лінійний) | порівнянь (бінарний) |
|---|---|---|
| X = 10 | ___ | ___ |
| перший елемент | ___ | ___ |
| відсутнє 21 | ___ | ___ |

Поломки:
1. `lo < hi`: останній кандидат не перевіряється. Вивід: ___
2. `lo = mid`: межі не рухаються, програма зациклюється. Вивід: ___
3. `(lo + hi) / 2`: переповнює `int` від 1 073 741 825 елементів; на 100 000 працює так само, як правильна (нічого не зламалося).
4. Невідсортований масив: із 100 запитів `-1` повернули ___.

## Завдання 3. Пошук межі

- Перший елемент ≥ 10: індекс ___, порівнянь ___ (лінійно ___).
- Елементів, рівних 10: ___, порівнянь ___ (лінійно 100 000).
- Порівнянь однакова кількість незалежно від числа елементів, рівних X: кожен крок відкидає половину діапазону.
- «Кратний 7»: метод повернув ___, правильно ___. Не працює, бо умова не монотонна (немає вигляду false…false true…true).

## Завдання 6. Висновок

1. Моя точка окупності: ___, лекційна: 34. Розбіжність через те, що секундомір міряє ще й `Array.Sort`, копіювання масиву й доступ до пам'яті.
